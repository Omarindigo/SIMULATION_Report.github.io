1. Abstract

This report documents the training of a humanoid locomotion agent using Soft Actor-Critic (SAC) on the MuJoCo physics engine via Gymnasium's Humanoid-v4 environment. The project began with Proximal Policy Optimization (PPO) but transitioned to SAC due to its superior sample efficiency, GPU utilization, and exploration characteristics. A total of 800,000 timesteps of training were completed, with checkpoints saved every 25,000 steps. Four key checkpoints (200K, 400K, 600K, 800K) were rendered at 1920 × 1080 resolution to visualise the progression of gait quality — from early-stage stumbling to stable, fluid locomotion at the final checkpoint. This page serves as both a report and a visual record of that progression.

2. Methodology

This project uses Stable-Baselines3 (SB3) to implement Soft Actor-Critic (SAC) as a reinforcement learning framework for continuous-control training. The methodology centres on how the agent is constructed, how experience is gathered, how learning occurs across timesteps, and how training progress is interpreted.

2.1 Reinforcement Learning Framework

The model is trained within a reinforcement learning setting in which an agent interacts with an environment over repeated cycles. At each timestep, the agent receives an observation of the environment, selects an action, receives a reward signal, and transitions to a new state. This loop produces the training data from which the policy is learned.

In this setup, Stable-Baselines3 provides the implementation infrastructure, while Soft Actor-Critic provides the learning logic. SB3 handles the neural network training pipeline, replay buffer management, optimisation loop, checkpointing, and interaction with Gymnasium or MuJoCo environments. SAC serves as the algorithmic core that updates the policy and value functions.

2.2 Choice of Algorithm: Soft Actor-Critic

Soft Actor-Critic is used because it is designed for continuous action spaces, which makes it suitable for robotic control, locomotion, articulated motion, and other environments where actions are real-valued rather than discrete. SAC is an off-policy algorithm, meaning that it stores previously collected transitions in a replay buffer and reuses them during training. This increases sample efficiency and stabilises learning.

The SAC framework consists of three interdependent components:

  • Actor network: learns a stochastic policy that maps observations to actions.
  • Critic networks: estimate the expected return of actions taken in particular states.
  • Target critic networks: stabilise learning by slowly tracking the critic parameters.

SAC also introduces an entropy objective, which encourages the policy to remain exploratory during training. Rather than collapsing immediately into a narrow deterministic behaviour, the agent continues to sample from a distribution over actions. This is important during early and middle stages of training, especially in environments where useful behaviour emerges gradually.

2.3 Environment and Agent Interaction

The training environment is instantiated through Gymnasium, typically with a continuous-control task such as MuJoCo locomotion. Once initialised, the agent begins interacting with the environment step by step.

Each timestep includes the following sequence:

  1. The environment provides the current observation.
  2. The actor network selects an action.
  3. The environment executes the action.
  4. A reward is returned.
  5. The resulting transition is stored in replay memory.

This sequence defines one timestep. Therefore, a label such as "400,000 timesteps" means that this interaction cycle occurred 400,000 times. It is a measure of training duration and data accumulation, not a measure of success by itself.

2.4 Data Collection and Replay Buffer

All interaction data is stored in a replay buffer. Each stored transition includes:

  • current state or observation
  • action taken
  • reward received
  • next observation
  • terminal or truncation flag

Because SAC is off-policy, the model does not train only on the newest transition. Instead, it repeatedly samples mini-batches from this replay buffer. This allows the agent to learn from a broader distribution of past experience and reduces the instability that can arise from relying only on recent rollouts.

2.5 Learning Procedure

Training proceeds iteratively during interaction with the environment. After enough transitions are collected, the model begins gradient-based updates. These updates occur in three linked stages:

Critic Update

The critic networks are trained to estimate the expected future return of state-action pairs. SAC uses twin critics to reduce overestimation bias. The target value is computed using target networks and the next-state policy distribution.

Actor Update

The actor network is trained to choose actions that maximise expected return while also preserving entropy. This means the policy is optimised not only for reward, but also for controlled stochasticity.

Target Network Update

The target critics are not copied abruptly. They are updated gradually through soft updates, which improves numerical stability and prevents oscillation.

This cycle repeats throughout training. Over time, the policy becomes better aligned with the reward structure of the environment.

2.6 Meaning of 400,000 Timesteps

The expression "400,000 Timesteps" refers to the total number of environment interaction steps used during training. It is therefore a description of the training horizon. In methodological terms, it marks the scale of exposure the agent has had to the task.

This number functions as a reporting condition in three ways:

  • It indicates the quantity of collected experience.
  • It identifies a checkpoint in the training trajectory.
  • It allows comparison with earlier or later runs.

A video titled with a specific timestep value shows the behaviour of the agent after that amount of training. It is a snapshot of the policy at that point in learning.

2.7 Implementation Procedure

A standard implementation procedure is as follows:

  1. Import the environment through Gymnasium.
  2. Instantiate the SAC model using SB3.
  3. Set the policy architecture, logging parameters, and device configuration.
  4. Train the model for a defined number of timesteps.
  5. Save checkpoints during training.
  6. Reload the trained model for evaluation or rendering.
  7. Assess behaviour qualitatively through rollout videos and quantitatively through episode rewards.

In code, this appears as: 

model = SAC("MlpPolicy", env, verbose=1)
model.learn(total_timesteps=400_000)
model.save("sac_model")

This sequence operationalises the methodology. The title in question is effectively the caption for the result of this process.

2.8 Evaluation and Interpretation

After training, the learned policy is evaluated by running the model in the environment without further optimisation. This stage may include visual rendering, reward logging, checkpoint comparison, and analysis of behavioural consistency.

The timestep value alone does not report evaluation metrics. It does not reveal whether the agent performed well, whether the reward converged, or whether the learned behaviour generalized robustly. It only identifies the library, the algorithm, and the total number of interaction steps. Methodologically, this means the timestep label should be interpreted as a training descriptor, not a full performance claim.

2.9 Rationale for This Setup

This methodology is appropriate when the task requires:

  • continuous motor output
  • iterative trial-and-error learning
  • stable training over long horizons
  • reuse of past experience
  • exploration that remains active during optimisation

SAC is well suited to these requirements because it balances reward maximisation with entropy regularisation, while SB3 offers a consistent and reproducible implementation environment.

4. Discussion

The progression from Figure 1 to Figure 4 demonstrates a clear trajectory of improvement. At 200K timesteps, the agent exhibits uncoordinated joint movements and frequent loss of balance. By 400K, basic stability emerges — the agent can maintain an upright posture for sustained periods. At 600K, a walking gait pattern becomes recognisable, and by 800K, locomotion is consistent and energy-efficient.

Several factors contributed to this outcome. The off-policy nature of SAC allowed efficient reuse of experience, which is particularly valuable in high-dimensional continuous control tasks. The entropy regularisation term ensured the agent continued exploring alternative gait strategies rather than converging to a suboptimal pattern early in training. The replay buffer size of 1M transitions provided sufficient diversity in the training distribution.

The transition from PPO to SAC proved critical. PPO's on-policy constraint limited the effective use of GPU parallelism, and its fixed exploration schedule was insufficient for the 17-DoF Humanoid action space. SAC's twin-Q critics addressed the value overestimation bias that would have caused PPO to overestimate the return of untested state-action pairs.
